# 死锁预防与检测教学案例

## 技能描述
本技能旨在帮助学生深刻理解死锁现象及其背后的理论。通过分析死锁产生的必要条件，学习如何从预防、避免、检测和解除四个维度来处理死锁问题，确保系统的稳定性。

- **课程名称**：操作系统 (Operating Systems)
- **核心章节**：进程管理 - 死锁 (Process Management - Deadlock)
- **前置知识**：进程概念、资源分配、同步与互斥

## 学习目标
1. **定义死锁**：理解死锁的定义及其与饥饿、死循环的区别。
2. **掌握四个必要条件**：互斥、不剥夺、请求并保持、循环等待。
3. **死锁预防策略**：学习如何通过破坏四个必要条件中的一个或多个来防止死锁发生。
4. **死锁避免 (银行家算法)**：深入理解“安全序列”的概念，并能执行银行家算法进行资源分配决策。
5. **检测与解除**：了解死锁检测图以及常用的死锁解除手段。

## 核心内容

### 1. 死锁的四个必要条件
只有当以下四个条件同时成立时，死锁才会发生：
- **互斥 (Mutual Exclusion)**：资源一次只能由一个进程使用。
- **请求并保持 (Hold and Wait)**：进程已保持至少一个资源，但又提出新的资源请求。
- **不剥夺 (No Preemption)**：资源不能被强制从进程中夺走，只能由进程自愿释放。
- **循环等待 (Circular Wait)**：存在一个进程等待序列，每个进程都在等待下一个进程持有的资源。

### 2. 死锁预防 (Deadlock Prevention)
通过设计系统协议来确保至少一个必要条件永远不会成立：
- **破坏“请求并保持”**：进程启动时一次性申请所有资源。
- **破坏“不剥夺”**：如果进程请求新资源被拒，则必须释放已持有的所有资源。
- **破坏“循环等待”**：对所有资源类型进行线性排序，规定进程必须按序号递增的顺序请求资源。

### 3. 死锁避免：银行家算法 (Banker's Algorithm)
核心思想是：在分配资源前，先计算分配后系统是否仍处于**安全状态**（即是否存在一个安全序列）。

**关键数据结构**：
- `Available`: 可用资源向量
- `Max`: 进程对资源的最大需求矩阵
- `Allocation`: 进程当前已分配资源矩阵
- `Need`: 进程尚需资源矩阵 (`Need = Max - Allocation`)

### 4. 死锁检测与解除
- **检测**：使用资源分配图 (Resource Allocation Graph) 进行简化，看是否能消除所有边。
- **解除**：
  - 资源剥夺法。
  - 撤销进程法（全部撤销或逐个撤销直到死锁消除）。

## 经典案例：银行家算法计算

**已知条件**：
系统有 3 类资源 (A:10, B:5, C:7)，当前时刻 T0：
- P0: Allocation(0,1,0), Max(7,5,3) -> Need(7,4,3)
- P1: Allocation(2,0,0), Max(3,2,2) -> Need(1,2,2)
- Available(3,3,2)

**提问**：此时系统安全吗？
**解答**：
1. 检查 P1：Need(1,2,2) <= Available(3,3,2)，可以分配。
2. P1 完成后释放资源，Available 更新为 (3,3,2) + (2,0,0) = (5,3,2)。
3. 接下来可检查其他进程... 最终若能找到完整序列（如 P1->P3->P4->P2->P0），则系统安全。
