## 内容

### 1. 临界资源与临界区
**临界资源**：一次只允许一个进程访问的共享资源（如打印机、共享变量）。

**临界区**：访问临界资源的那段代码。

### 2. 同步与互斥
**互斥（Mutual Exclusion）**：多个进程不能同时进入临界区。
- 目的：保护临界资源
- 例子：两个进程不能同时写同一个文件

**同步（Synchronization）**：进程间的执行顺序协调。
- 目的：保证逻辑正确性
- 例子：生产者-消费者问题中，消费者必须等生产者生产后才能消费

### 3. 信号量（Semaphore）
信号量是一个整型变量，配合两个原子操作：
- **P操作（wait）**：`S = S - 1`，若 S < 0 则阻塞
- **V操作（signal）**：`S = S + 1`，若 S ≤ 0 则唤醒一个等待进程

**互斥信号量**：初值为1，用于实现互斥访问
**同步信号量**：初值可为0或其他值，用于进程间同步

## 经典案例

### 案例1：生产者-消费者问题
**问题描述**：
- 生产者进程生成数据放入缓冲区
- 消费者进程从缓冲区取数据消费
- 缓冲区大小有限（如10个槽位）

**解决方案**：
```c
Semaphore mutex = 1;      // 互斥访问缓冲区
Semaphore empty = 10;     // 空槽位数
Semaphore full = 0;       // 已用槽位数

// 生产者
while(true) {
    生产数据item;
    P(empty);          // 等待空槽位
    P(mutex);          // 进入临界区
    将item放入缓冲区;
    V(mutex);          // 离开临界区
    V(full);           // 增加已用槽位
}

// 消费者
while(true) {
    P(full);           // 等待有数据
    P(mutex);          // 进入临界区
    从缓冲区取出item;
    V(mutex);          // 离开临界区
    V(empty);          // 增加空槽位
    消费item;
}
```

**关键点**：
1. 必须先执行同步P操作（empty/full），再执行互斥P操作（mutex）
2. 否则可能造成死锁

### 案例2：读者-写者问题
**问题描述**：
- 多个读者可以同时读
- 写者写时，不允许其他读者或写者访问

**解决方案**：
```c
Semaphore rw = 1;         // 读写互斥
Semaphore mutex = 1;      // 保护readcount
int readcount = 0;        // 读者计数

// 读者
P(mutex);
readcount++;
if(readcount == 1) P(rw); // 第一个读者加锁
V(mutex);

读数据;

P(mutex);
readcount--;
if(readcount == 0) V(rw); // 最后一个读者解锁
V(mutex);

// 写者
P(rw);
写数据;
V(rw);
```

## 常见错误

1. **PV操作顺序错误**：先mutex后同步信号量 → 可能死锁
2. **忘记配对使用**：只有P没有V → 永久阻塞
3. **信号量初值错误**：互斥信号量初值不为1 → 无法正确互斥

## 实战技巧

1. **分析步骤**：
   - 找出临界资源和临界区
   - 确定需要互斥还是同步
   - 设置合适的信号量及初值
   - 正确安排PV操作顺序

2. **记忆口诀**：
   - 互斥信号量初值1
   - 同步信号量看情况
   - 先同步后互斥，避免死锁

3. **验证方法**：
   - 检查能否实现互斥
   - 检查会不会死锁
   - 检查能否完成同步
